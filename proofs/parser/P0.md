# P0: the Lean reference parser against the Rust parser

Stage P0 of `PLAN.md`, Lean side. The reference parser `SudoersSpec.Syntax.parseSudoers`
(`proofs/spec/SudoersSpec/Syntax/`, see its README) is compared with the Rust parser through
the parser dump of `DUMP.md`. Evidence kind: test (only the inputs run). The comparison with
C sudo is `C-SUDO.md`.

## Current method (dump v2)

1. Corpus: `parser corpus SEED N` (`Differential/ParserCorpus.lean`): `N` cases per grammar
   category and per mutation operator, plus the 24 fixed inputs of category `known` (PLAN.md 3.3,
   F-P1 to F-P6).
2. Rust dump: `cargo test --lib sudoers::test::parser_dump::dump_corpus` (`DUMP.md` section 6):
   `parse_lines::<Sudo>` of the crate in a `cfg(test)` build, with the fixture tree created, and
   the character-class table of the toolchain (`write_char_table`, Unicode 17.0.0).
3. Lean dump: `parser lean-dump CORPUS CHARTABLE` (`ParserMain.lean`,
   `Differential/ParserDump.lean`): `parseSudoersWith Descriptions.test O` on every case, printed
   in the same format. Test oracles (`Differential/ParserOracles.lean`): the character classes
   read from the Rust table; `canonicalize` on a model of the fixture tree of `DUMP.md` section 5
   (with Rust `Path` component rules and `realpath` on the modelled symbolic links), every other
   path absent; glob compilation by the error rule of `DUMP.md` section 5. The dump prints
   each parsed settings modifier with its setting name and exact payload.
4. Comparison: `parser_lean_compare.py`, byte for byte per case; a case the Rust harness lists in
   `.hostdep` (an accepted command pattern that names an existing host path) is counted apart.

All of it: `cd proofs/differential && ./parser-lean-run.sh N SEED...` in the dev shell.

The Rust side is the parser of the branch (`d84ff98a` and later: the M1 restyle of the lexical
layer, the settings data API); its equivalence with `70fdb56b` is the restyle's evidence
(`RESTYLE.md`). Independently, the spec tests of the reference parser (603 `#guard`s and 100
kernel-checked examples in `Syntax/Tests*.lean`) have expected values produced by the code at
`70fdb56b` itself.

## Historical result (dump v1)

The runs below compared the v1 dump, whose settings records showed only the effect of each
modifier on two fixed bases. Agreement here is agreement of those observations, not of
the modifiers' identities or full payloads. These runs were not repeated in v2.

| Seed | N | Cases | Records | Agree | Differ | Host-dependent (all agree) |
|---|---|---|---|---|---|---|
| 1 | 200 | 5,824 | 18,958 | 5,824 | 0 | 1 |
| 2 | 1000 | 29,024 | 94,142 | 29,024 | 0 | 4 |
| 3 | 1000 | 29,024 | 94,218 | 29,024 | 0 | 4 |
| **total** | | **63,872** | **207,318** | **63,872** | **0** | 9 |

No disagreement; no panic on either side. The host-dependent cases name `/etc/passwd`-like
paths that canonicalize to themselves on the machine used, so they agree as well.

Cases per category (seeds 2 and 3 each; seed 1 has 200 where these have 1000): `alias`,
`blank`, `command`, `continuation`, `defaults`, `eof`, `fixture`, `host`, `include`,
`listlimit`, `maxlen`, `mixed`, `rule`, `runas`, `tag`, `unicode`, `user`, `valid`,
`whitespace`: 1,000 each; `known`: 24; mutations (`delete-char`, `delete-token`,
`duplicate-char`, `duplicate-token`, `insert-char`, `replace-char`, `splice-lines`, `swap-char`,
`swap-token`, `truncate`), each spread over the grammar categories it was applied to: 1,000
each. Per-category tables are in the `report.md` that the run writes.

Local CPU: about 3 minutes for all three seeds (Rust and Lean dumps together; the Lean dump of
29,024 cases takes about 15 s).

## Format v2 check

The Rust and Lean dump executables matched the expected v2 records on nine hand-picked
settings-only inputs. The inputs exercised distinct list removals, list modes and order
with duplicates, and scalar payloads. Direct constructor tests also distinguished
`none` from a present empty string. The C comparator's extraction of names (including
multiplicity) was checked with synthetic JSON only, not by running C sudo.

## Cluster command (current format)

The cluster has elan with Lean 4.36.0-rc2 under `$OMNIRUN_ROOT/cache/sudo-rs-lean/elan` and a
Rust toolchain; `proofs/spec` and `proofs/differential` build there. From the repository root:

```sh
export ELAN_HOME=$OMNIRUN_ROOT/cache/sudo-rs-lean/elan PATH=$OMNIRUN_ROOT/cache/sudo-rs-lean/elan/bin:$PATH
cd proofs/differential
PARSER_SCRATCH=$SCRATCH/p0-lean ./parser-lean-run.sh 20000 1 2 3 4 5 6 7 8
```

(`N = 20000` gives 580,024 cases per seed; the exit status is 1 if any case disagrees, and
`$PARSER_SCRATCH/seed-*/differences.txt` lists them with both dumps.)

## Behaviour transcribed as is

The reference parser transcribes the legacy code, including its surprising parts; they are listed
in `proofs/spec/SudoersSpec/Syntax/README.md` ("Rust behaviour transcribed as is"). Behaviour not
already described in `PLAN.md`, by category (details kept locally): lexical layer 2, tokens 3,
productions 6, settings 4. None of them is a panic or a crash reachable from a sudoers file.
